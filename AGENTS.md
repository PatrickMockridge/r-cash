# AGENTS.md

Operating instructions for coding agents working in this repository. Read this before
changing code, contracts or documentation.

## What this repository is

R-Cash is a permissionless multi-currency account and cross-border payments network on
rholo. It issues per-currency REV-collateralised stablecoins, runs a DAI-shaped issuer
(vaults, liquidation, surplus buffer, savings, PSM), provides a full mesh of direct FX
markets, and exposes accounts, claimable transfers, a Rust SDK/CLI/WASM and a React web
client. It is a v0.5, devnet-only prototype; there is no audit and no mainnet deployment.

The directory is named `Rholphin` after the Lean specification package (`spec/lean/`), not
after a separate product. The product is R-Cash.

## Authority order

When sources disagree, use this order:

1. **Contracts and formal core** — `contracts/src/`, `docs/spec/00-CALCULUS.md`,
   `10-COMPONENTS.md`, `20-INVARIANTS.md`, `30-WIRING.md`, `docs/spec/flows/*.yaml`,
   `spec/lean/`, `spec/tla/`.
2. **Product behaviour** — `docs/SPEC.md`. It wins for product and client behaviour. A
   contradiction with the formal core is a defect in one of them.
3. **Evidence** — `docs/spec/acceptance.yaml`, `checks.yaml`, `model.yaml`, `harness/`,
   `tests/`.
4. **Explanation** — `book/`. If the book and a normative source disagree, the normative
   source wins and the book must be fixed.

Do not invent a behaviour, parameter, address, campaign result or status. If you cannot
trace a claim to a source, do not write it.

## Commands

### Offline and static gates

```sh
make venv                 # Python harness dependencies
make spec-check           # build + measure + architecture + captures
make formal-check         # Lean + flows + traceability + mesh
make check-languages      # language policy
make pre-devnet-check     # full static + Rust + WASM + web gates
cargo test --workspace --exclude rcash-wasm
cargo check -p rcash-wasm --target wasm32-unknown-unknown
npm --prefix web run typecheck
npm --prefix web test
```

### Devnet

```sh
make devnet               # start a one-validator rholo devnet
make keys                 # idempotent; --fresh to regenerate
make install              # 17-step signed-read installer
make bootstrap            # stablecoin and market acceptance suites
make demo                 # send -> claim CLI journey
make down                 # stop and remove
```

### Behavioural suites

```sh
make unit-stablecoin      # one suite
make unit-all             # ordered campaign list
```

Each suite needs a running devnet with the components installed.

### Public testnet

All testnet commands are opt-in, read `configs/testnet.json`, require `--allow-live` and use
fresh keys under `.testnet/`. Never reuse devnet keys.

```sh
make testnet-preflight
make testnet-keys
make testnet-fund
make testnet-install
make testnet-setup
make testnet-campaign
```

### Docs

```sh
make docs                 # build to book/book
make docs-serve           # serve at http://localhost:3000
make docs-check           # build + link check
```

mdBook plugins required: `mdbook`, `mdbook-mermaid`, `mdbook-katex`, `mdbook-toc`,
`mdbook-linkcheck2`.

## Rules

### Generated files — do not edit

- `docs/spec/flows/*.md` — generated from the matching YAML; edit the YAML and run
  `make flows`.
- `docs/spec/flows/TRACEABILITY.md` and `RECONCILIATION.md` — generated.
- `contracts/build/*` — generated by `tools/build_contracts.py`.
- `deployments/*.json` — generated manifests; write only through the installer.
- `book/book/` — build output; ignored.

`README.md`, `CAMPAIGN.md` and `REFUSAL-DECISIONS.md` inside `docs/spec/flows/` are
hand-written and may be edited.

### Behaviour changes

A behaviour change is a spec change. Update, in order:

1. the contract in `contracts/src/`;
2. the flow YAML (arm, guards, effects, access, refusals, invariants);
3. the Lean model if a transition or invariant obligation changes;
4. `docs/SPEC.md` if product behaviour changes;
5. `docs/spec/acceptance.yaml` with criteria and checks;
6. the harness/model tests and vectors;
7. the arm inventory and generated flow docs (`make inventory`, `make flows`);
8. the book if the explanation or a status claim changes.

Then run `make formal-check` and `make spec-check`.

### Language policy

The project is Rust, Rholang, Python and TypeScript, with Lean 4 and TLA+ specifications.
`tools/check_languages.py` rejects native sources, native-compiling crates, native build
tools and native artifacts. Do not add a native dependency or a C/C++ toolchain.

### Documentation

- The book explains and links; it does not duplicate requirement tables, acceptance
  criteria, refusal strings or arm-level detail.
- Every status claim must be dated and traceable. A planned or blocked item is never
  presented as done.
- Update the book and `README.md` for user-visible changes; run `make docs-check`.
- Links to normative files use GitHub URLs; internal book links are relative Markdown.

### Secrets and safety

- Never commit private keys, keystores, claim secrets or `.devnet/`/`.testnet/` state.
- The browser key stays in WASM; the keystore is encrypted in IndexedDB; a claim secret
  lives only in the URL fragment. Do not put a secret in localStorage or the DOM.
- Do not run a testnet command without `--allow-live`.
- Do not retry a value-moving deploy blindly. Use the op cache or a new operation id.
- A BLOCKED campaign stage is never a pass.

## Platform pitfalls

- Deploy terms are capped at **65,536 bytes**; parser depth at **128**.
- A failed deploy rolls back tuple space and native REV/ERTP state. After value moves, a
  refusal must fail the deploy (`1/0`), not reply `false`.
- An unmatched `for` is silent. Every arm must reply or be deliberately fire-and-forget.
- BigInt intermediates need `.toInt()` at fixed-point boundaries.
- A name bound by a receive used as a send argument needs `*x`; a value bound by `@x` is
  passed bare. Mixing them is a parse error.
- The devnet shard is `/root`; the public testnet shard is `/testnet`.
- `validAfterBlockNumber` anchors a 50-block lifespan. A deploy anchored at 0 is never
  proposed.
- `explore-deploy` has no block context; freshness-gated reads must be signed deploys.
- The native client has no TLS backend; use direct HTTP endpoints for CLI/SDK writes.
- Hostlist entries are advisory and re-verified; a write is sent to exactly one node and is
  never re-submitted elsewhere.

## Definition of done

- [ ] The change is implemented in the contract and reflected in the flow YAML and Lean
      model when behaviour changed.
- [ ] `make spec-check` and `make formal-check` pass.
- [ ] Relevant offline tests pass; the relevant `make unit-*` suite passes on a devnet.
- [ ] `make check-languages` passes.
- [ ] Generated files are regenerated, not hand-edited.
- [ ] `docs/SPEC.md`, `acceptance.yaml` and `checks.yaml` agree with the change.
- [ ] `book/` and `README.md` are updated for user-visible changes.
- [ ] `make docs-check` passes.
- [ ] No stale references to removed files, no secrets, no invented status claims.

If a check cannot run (no devnet, no Lean, no testnet), say so explicitly and report the
result as blocked or not run. Do not report an unrun check as passing.
